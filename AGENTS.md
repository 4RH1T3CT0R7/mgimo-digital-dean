# Правила проекта для ИИ-агентов

Этот файл читают Codex (напрямую) и Claude Code (через `CLAUDE.md` → `@AGENTS.md`). Правила одинаковы для всех агентов и всех участников.

## Проект

Прототип личного кабинета студента МГИМО для конкурса «Цифровой деканат будущего». Это **концепт, а не официальный сервис**; все данные вымышленные. Сдача 22.11, прототип должен работать до 28.11.

Перед любой работой прочитай:
1. `docs/progress.md` — где мы сейчас;
2. **свою задачу** в `docs/tasks/` — делай только то, что в ней, раздел «Что не входит» соблюдай строго;
3. контракты, на которые ссылается задача, в `docs/contracts/`;
4. при необходимости — `docs/architecture.md`, `docs/security.md`, `docs/requirements.md`, `docs/decisions.md`.

## Стек и структура

- Микросервисы на Go (`services/auth|academic|requests|notifications|assistant`) в монорепозитории с **одним `go.mod`**; общий код — `pkg/`.
- PostgreSQL (у каждого сервиса своя БД), NATS JetStream для событий, Caddy как шлюз.
- Фронтенд: React + Vite + TypeScript, TanStack Query, Tailwind + shadcn/ui, PWA. Соглашения — `frontend/README.md`.
- Как работать с задачей (промпт, проверка, PR) — `docs/tasks/README.md`.
- Подробно: `docs/architecture.md` §6–7.

## Обязательные правила

### Контракты
1. API меняется **только через контракт**: `docs/contracts/<сервис>.yaml`, затем `make gen`. Типы запросов и ответов руками не пишутся.
2. **Сгенерированный код не редактируется**: `services/*/internal/api`, `services/*/internal/db`, `pkg/clients`, `frontend/src/api`.
3. Контракт чужого сервиса не меняй: остановись и напиши, что нужно изменить и зачем, — решает капитан.
4. События публикуются и читаются только через `pkg/events`; JSON событий руками не собирается.

### Границы сервисов
5. Сервис работает **только со своей БД**. Чужие данные — через клиент внутреннего API (`pkg/clients`) или через события.
6. Нельзя импортировать код `services/<другой>/...`. Общее выносится в `pkg/` (только по задаче).
7. Новый сервис или модуль делается по образцу `services/auth` (эталон).

### Безопасность (см. `docs/security.md`)
8. Личность пользователя берётся **только** из middleware `pkg/platform` (заголовки `X-User-*` от шлюза). ID владельца **никогда** не берётся из URL или тела запроса.
9. Эндпоинты студента — `/me/...`. Каждый SQL-запрос к пользовательским данным фильтруется: студент — по своему ID, сотрудник — по своему факультету, администратор — без фильтра.
10. Чужой или несуществующий объект → **404**, не 403.
11. Секреты — только из переменных окружения. Никаких ключей, паролей и токенов в коде, git, логах и во фронтенде.
12. В логах только ID и типы событий, без ФИО и других персональных данных.
13. Из браузера никаких запросов к сторонним доменам: шрифты, иконки и скрипты размещаются у нас.
14. Только вымышленные данные. Реальные ФИО запрещены; реальные названия факультетов МГИМО разрешены.

### Фронтенд
15. Сначала мобильная версия: всё работает на ширине **360 px**.
16. На каждом экране есть состояния **загрузка / пусто / ошибка**.
17. Данные с сервера — через TanStack Query и сгенерированный клиент. Компоненты — из `src/shared/ui`.
18. Тексты интерфейса — на русском, понятные без инструкций. Доступность: подписи полей, контраст, работа с клавиатуры.

### Качество и проверка
19. Бизнес-правила и проверки доступа покрыты Go-тестами. Перед PR: `make gen` без изменений, `make test` зелёный, для фронтенда — `make e2e`.
20. **Проверяй, что изменение действительно применилось** (перечитай файл, запусти, поищи строку). Код возврата команды — не доказательство.
21. Зависимость добавляется только при реальной необходимости и упоминается в PR. Сначала — стандартная библиотека и то, что уже подключено.
22. Не расширяй объём задачи. Заметил проблему вне задачи — опиши её в PR, но не чини.

### Git
23. Ветка на задачу: `tNN-кратко` (например, `t07-requests-api`). В `main` напрямую не пушим — только через PR.
24. Сообщения коммитов: `feat(requests): …`, `fix(academic): …`, `docs: …`, `test(auth): …`. Описание — по-русски.
25. Если агент ошибся и ошибку исправили — добавь запись в `docs/process/ai-mistakes.md` (это материал для жюри).
26. Если ты не владелец каталога (таблица ниже), не меняй в нём файлы. Нужна правка — опиши её в PR или задаче для владельца.

## Команды

Появятся в задаче каркаса проекта; до неё могут не существовать.

| Команда | Что делает |
|---|---|
| `make gen` | Генерация кода из контрактов и SQL |
| `make test` | Go-тесты |
| `make up` | Поднять всё в Docker Compose |
| `make e2e` | Playwright-сценарий жюри на 360 px |
| `make lint` | Линтеры |

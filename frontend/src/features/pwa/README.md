# T16: PWA и локальное хранение

`vite-plugin-pwa` 2.0.0 поддерживает Vite 8. Конфигурация — `config.ts`; цвета манифеста читаются из `src/index.css`, иконки пока содержат простой знак «ЦД» до выбора командой T17.

Service worker создаётся только при production-сборке. Он предварительно кэширует файлы сборки и не имеет правил runtimeCaching. `/api`, `/api/*` и `/api?...` исключены из навигационного fallback. MSW worker не попадает в production. В `dev:mock` PWA worker выключен, чтобы два worker не конкурировали за корневую область.

При выходе и 401 событие `onLogout` очищает Cache Storage целиком, ключ `theme` и ключи приложения с префиксом `mgimo:`. Чужие ключи localStorage не удаляются. Очистка localStorage выполняется и при ошибке Cache Storage. После выхода холодное открытие без сети не гарантируется: кэш был удалён; личные данные офлайн намеренно не предоставляются. Обычный онлайн-запрос статики при промахе precache идёт в сеть (стандартная стратегия Workbox).

Кнопка экспорта отправляет `fetch` с credentials include и cache no-store, задаёт сегодняшнюю московскую дату `from`, а конец семестра оставляет API. При выходе запрос прерывается, файл после выхода не создаётся. Blob URL освобождается после начала скачивания. Ответ 401 завершает сессию, как сгенерированные клиенты.

В `dev:mock` экспорт формируется MSW из общего состояния расписания T14: перенос и аудитория попадают в файл, отменённые занятия и исходные строки переноса исключаются. Начало периода по умолчанию — сегодня по Москве, конец — 27.12.2026, как в seed. Production продолжает скачивать готовый файл сервиса academic.

Проверено автоматически: P1–P4, установка по событию beforeinstallprompt, Safari/iOS, установленный режим, очистка при выходе и сбоях хранилища, отмена скачивания и 401. Дополнительно — кнопка с настоящим MSW, содержимое файла, фильтрация и последовательные изменения расписания. Всего 24 теста T16, 144 с T09/T14. Типы, линтер, сборка, генерация API без diff проходят. В сборке — manifest.webmanifest, registerSW.js, sw.js, Workbox и три PNG-иконки.

Ручная приёмка ещё не завершена. Средство Windows Computer Use остановилось до действий в Chrome, так как не смогло надёжно определить адрес текущей страницы. Скриншотов Manifest, Cache Storage и установленного приложения пока нет; успешная сборка не заменяет эти проверки.

После появления стенда:

1. Открыть production-сборку в обычном Chrome, DevTools → Application → Manifest: проверить отсутствие ошибок и размеры иконок. Установить приложение, сохранить снимок.
2. Войти, открыть расписание, убедиться, что Cache Storage содержит только статику. Выйти, обновить список кэшей: ответов `/api/*` нет. Сохранить снимок.
3. Проверить переход offline/online и кнопку «В календарь» на 360 px в обеих темах.
4. Импортировать скачанный файл в календарь телефона. Серверный файл T04 ранее проверен в веб-версии Google Calendar (PR #20), но это не проверка нового UI и телефона.

Источники для реализации: [Workbox generateSW](https://vite-pwa-org.netlify.app/workbox/generate-sw.html), [регистрация worker](https://vite-pwa-org.netlify.app/guide/register-service-worker), [импорт в Google Calendar](https://support.google.com/calendar/answer/37118), [руководство Apple](https://support.apple.com/guide/iphone/set-up-mail-contacts-and-calendar-accounts-ipha0d932e96/ios).

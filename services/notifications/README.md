# Сервис уведомлений

В PR1 реализованы лента студента, дедлайны, отметки о прочтении и три подписки JetStream. Обработчики используют принадлежность студента из внутреннего API academic. SQL ограничивает запросы этим адресатом и читает отметки только текущего студента.

Для локальных тестов запустите PostgreSQL 17 с пользователем, имеющим право создавать тестовые базы. Передайте `TEST_DATABASE_URL` и `REQUIRE_DB_TESTS=1`, затем запустите `go test ./services/notifications/...`. В тестах academic заменён HTTP-заглушкой, а JetStream запускается в процессе тестов. Публичные типы генерируются из неизменённого OpenAPI, запросы — через sqlc 1.28.0.

## Хранение и повторная доставка

У события занятия несколько строк уведомлений, по одной на группу. Частичный уникальный индекс покрывает `(source_event_id, audience_group_id)` с `NULLS NOT DISTINCT`. Для личного события группа равна `NULL` и на исходный ID остаётся одна строка. Для публикаций без события индекс не применяется. Вся рассылка занятия сохраняется в одной транзакции.

SQL seed содержит тексты T19, объявления, новости и сроки из `seed.md`. Уведомления о занятиях и заявках приходят по штатным событиям после заполнения тестовых данных соседних сервисов.

## PR2 — кабинет сотрудника

Сотрудник публикует объявления и создаёт дедлайны только внутри своего факультета. Для группы её факультет проверяется через `getGroup`. Администратор также может публиковать для всех. Списки и операции с конкретной записью используют SQL-фильтр по факультету. Состав отчёта об ознакомлении берётся из `resolveAudience`. Число прочтений в списке берётся из сохранённых отметок, а отчёт отражает текущий состав адресатов.

Внутренний контракт academic не даёт короткое название факультета по его ID. Подписи для факультетов из seed используют их общие ID, для остальных выводится «Деканат». Связанная услуга сохраняется как ID из публичного API. Notifications проверяет, что ссылка указана для срока подачи заявлений. Проверка существования факультета по ID и услуги по ID потребовала бы дополнительных вызовов к справочникам. Клиенты T13 выбирают значения из справочников.

## Проверка

- R1, R2, N1–N8 и S1–S6 прошли на PostgreSQL 17. E1–E2 прошли с JetStream. Повторное сообщение доставлено потребителю и подтверждено. Число записей осталось равным двум.
- `go test -count=1 ./...` с `REQUIRE_DB_TESTS=1` и `go vet ./...` прошли. На первой проверке кластер с локалью C не поддержал поиск без учёта регистра кириллицы в тесте requests. Повтор на C.UTF-8 прошёл.
- Локальный Caddy по HTTPS проверен с реальными сервисами auth, academic, requests и notifications, PostgreSQL и NATS. Применены SQL seed и запущены штатные `-seed-events`. Входили под `student.mo`, `student.meo` и `dekanat.mo` с временным паролем для локальной БД. Проверены лента, изоляция ФМО/МЭО, публикация, подтверждение, счётчики, отчёт, создание и удаление дедлайна.
- `make gen` прошёл без изменений результатов генерации. Вместо контейнера использовался локальный sqlc той же версии 1.28.0. Штатный Compose и браузерный прогон экранов T11/T13 остаются отдельной проверкой.

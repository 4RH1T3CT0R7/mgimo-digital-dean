# Сервис уведомлений

В PR1 реализованы лента студента, дедлайны, отметки о прочтении и три подписки JetStream. Обработчики используют принадлежность студента из внутреннего API academic. SQL ограничивает запросы этим адресатом и читает отметки только текущего студента.

Для локальных тестов запустите PostgreSQL 17 с пользователем, имеющим право создавать тестовые базы. Передайте `TEST_DATABASE_URL` и `REQUIRE_DB_TESTS=1`, затем запустите `go test ./services/notifications/...`. В тестах academic заменён HTTP-заглушкой, а JetStream запускается в процессе тестов. Публичные типы генерируются из неизменённого OpenAPI, запросы — через sqlc 1.28.0.

## Хранение и повторная доставка

У события занятия несколько строк уведомлений, по одной на группу. Частичный уникальный индекс покрывает `(source_event_id, audience_group_id)` с `NULLS NOT DISTINCT`. Для личного события группа равна `NULL` и на исходный ID остаётся одна строка. Для публикаций без события индекс не применяется. Вся рассылка занятия сохраняется в одной транзакции.

SQL seed содержит тексты T19, объявления, новости и сроки из `seed.md`. Уведомления о занятиях и заявках приходят по штатным событиям после заполнения тестовых данных соседних сервисов.

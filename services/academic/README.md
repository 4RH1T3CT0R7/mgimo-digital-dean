# academic — T04 PR1

Первая часть T04: схема всех таблиц `academic`, внутренний API и базовые вымышленные данные.
Публичный API профиля, расписания и оценок, события и оставшиеся тестовые данные относятся к PR2.

## Запуск

Как у `auth`: `DATABASE_URL` задаётся через окружение; при старте применяются встроенные миграции goose.
`cmd/main.go` собирает зависимости и запускает два HTTP-сервера через `pkg/platform`.

На порту **8080** в PR1 доступен только `/healthz`.
На порту **8081** доступны `/healthz` и внутренние операции:

| Метод и путь | Назначение |
|---|---|
| `GET /internal/students/{student_id}` | Карточка для слепка в заявке |
| `GET /internal/students/{student_id}/membership` | Факультет, курс, академическая и языковые группы |
| `GET /internal/groups/{group_id}` | Данные и факультет группы |
| `POST /internal/audience/students` | Адресаты `all`, `faculty`, `course`, `group`, `user` |

Внутренние пути не зарегистрированы на публичном сервере. Отсутствующие объекты возвращают JSON-404;
неверный адресат — JSON-400 с ошибками полей. Пустой список адресатов — `{"students":[]}`.

## Данные и генерация

- `migrations/00001_init.sql` создаёт все 13 таблиц из `docs/contracts/data-model.md`.
- `seed/00_reference.sql` загружается штатным `make seed`: четыре факультета, две программы,
  текущий семестр, шесть групп, два тестовых студента и по девять одногруппников без аккаунтов,
  12 преподавателей и 10 дисциплин. Общие ID и профили — из `docs/contracts/seed.md`.
- `queries/academic.sql` — исходные SQL-запросы. `sqlc.yaml` повторяет конфиг `auth`.
- `make gen` генерирует SQL-обёртки и интерфейсы из контрактов. Сгенерированные файлы вручную не меняются.

## Проверка

Задать `TEST_DATABASE_URL` для отдельного локального PostgreSQL, затем:

```sh
REQUIRE_DB_TESTS=1 go test ./services/academic/...
go vet ./...
```

Тесты I1–I4 сами создают данные и не зависят от seed. Дополнительные проверки: языковые адресаты,
разделение факультетов и курсов, неверные UUID и JSON, пустые ответы, разделение портов,
совпадение seed с общим контрактом и отсутствие имён в логах. Каждый тест работает в отдельной БД.

# academic — T04

Профиль, расписание, успеваемость и управление изменениями занятий.
Сервис хранит учебные данные, рассчитывает показатели успеваемости и публикует события об изменениях расписания.

## Запуск

Как у `auth`: `DATABASE_URL` и `NATS_URL` задаются через окружение; при старте применяются встроенные миграции goose.
`cmd/main.go` собирает зависимости и запускает два HTTP-сервера через `pkg/platform`.

На порту **8080** доступны `/healthz`, `/faculties`, `/me/profile`, `/me/schedule`, `/me/schedule.ics`,
`/me/grades/{summary,current,sessions}`, `/me/academic-calendar` и `/staff/{groups,lessons}` с изменением занятия
через `POST /staff/lessons/{id}/change`. Личность читается только через `pkg/platform`:
`/me/*` — студент, `/staff/*` — сотрудник своего факультета или администратор.
На порту **8081** доступны `/healthz` и внутренние операции:

| Метод и путь | Назначение |
|---|---|
| `GET /internal/students/{student_id}` | Карточка для слепка в заявке |
| `GET /internal/students/{student_id}/membership` | Факультет, курс, академическая и языковые группы |
| `GET /internal/groups/{group_id}` | Данные и факультет группы |
| `GET /internal/faculties/{faculty_id}` | Короткое название факультета для подписи «Деканат ФМО» |
| `POST /internal/audience/students` | Адресаты `all`, `faculty`, `course`, `group`, `user` |

Внутренние пути не зарегистрированы на публичном сервере. Отсутствующие объекты возвращают JSON-404;
неверный адресат — JSON-400 с ошибками полей. Пустой список адресатов — `{"students":[]}`.

## Данные и генерация

- `migrations/00001_init.sql` создаёт все 13 таблиц из `docs/contracts/data-model.md`.
- `seed/00_reference.sql` загружается штатным `make seed`: четыре факультета, две программы,
  текущий семестр, шесть групп, два тестовых студента и по девять одногруппников без аккаунтов,
  12 преподавателей и 10 дисциплин. Общие ID и профили — из `docs/contracts/seed.md`.
- `seed/01_schedule.sql` создаёт 672 занятия на семестр: по 3 академические пары и 1 языковой в будни;
  по переносу, отмене и смене аудитории в каждой неделе 16.11–06.12 для обоих тестовых студентов.
- `seed/02_grades.sql` создаёт результаты прошлых семестров, 6 текущих дисциплин на студента,
  по 3 контрольные точки и рейтинги. У student.mo светофор 3/2/1, у student.meo один долг.
- `migrations/00002_term_periods.sql` и `seed/03_academic_year.sql` — календарный план (D62): учёба до 20.12,
  зачётная неделя 21–27.12, праздники, сессия 11–24.01, каникулы до 07.02. В seed — зачёты декабря,
  консультации и экзамены января с настоящими аудиториями (даты — как у дедлайнов notifications);
  пары зачётной недели и пара, совпавшая с зачётом, удаляются; формы контроля текущих дисциплин
  следуют сессии; конец семестра сдвигается на последний день сессии. Файл ложится и поверх 00–02.
- `queries/*.sql` — исходные SQL-запросы. `sqlc.yaml` повторяет конфиг `auth`.
- `make gen` генерирует SQL-обёртки и интерфейсы из контрактов. Сгенерированные файлы вручную не меняются.

## Проверка

Задать `TEST_DATABASE_URL` для отдельного локального PostgreSQL, затем:

```sh
REQUIRE_DB_TESTS=1 go test ./services/academic/...
go vet ./...
```

Тесты I1–I4, A1–A21 сами создают данные и не зависят от seed. G1–G4 и C1–C2 — чистые расчёты.
Дополнительно проверяются изоляция данных, конкурентные переносы, сохранение исходной пустой аудитории,
сбой публикации после коммита, экранирование и перенос UTF-8 строк в iCalendar, полный seed
и устойчивые ID повторных событий. Каждый тест с БД получает отдельную базу.

## Изменения и события

Строка занятия блокируется на время транзакции. Исходные значения сохраняются при первом изменении;
следующие изменения их не заменяют, в том числе если исходная аудитория была пустой.
После переноса смена аудитории сохраняет статус `moved`, поэтому прежнее место остаётся видно как `moved_away`.
Отменённое занятие изменить нельзя. Событие публикуется через `pkg/events` после коммита;
сбой NATS записывается по ID и типу события и не отменяет результат запроса.

Флаг `-seed-events` публикует события всех изменённых занятий с ID `uuid.NewSHA1` от ID занятия.
Повторный запуск возвращает те же ID; `deploy/seed.sh` вызывает этот режим для academic.

## Календарь

Без параметров `/me/schedule.ics` экспортирует занятия с сегодняшнего дня до конца семестра (конца сессии);
ограничение 31 день относится только к JSON-расписанию. Отмены и виртуальные записи не экспортируются.
У зачёта, консультации и экзамена вид стоит в названии; контрольные точки — события на весь день.
Файл использует CRLF, экранирование текстовых полей, перенос строк по 75 октетов без разрыва UTF-8
и `VTIMEZONE` для Europe/Moscow. Импорт файла в календарь телефона/Google Calendar проверяется вручную по ТЗ.

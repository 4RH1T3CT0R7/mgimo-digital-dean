# Локальная проверка настоящих API: T04, T09, T14, T15

**Дата:** 09.11.2026, 15:33 МСК. **Исполнитель:** Всеволод Омельченко / Codex.

Все **11 групп проверок прошли**. Это HTTP-проверка настоящих сервисов `auth`, `academic`, `requests`, PostgreSQL, NATS JetStream и Caddy — без MSW и подмен ответов API. Исходный код сервисов: коммит [`17b0af2`](https://github.com/4RH1T3CT0R7/mgimo-digital-dean/commit/17b0af2204991f354380f371283777c5710d59bd). Машиночитаемый результат: [runtime-api-check.json](runtime-api-check.json).

## Условия запуска

- Windows; Go 1.26.10, PostgreSQL 17.11 с ICU, установленный ранее NATS; официальный Caddy 2.11.9. SHA-256 архива Caddy проверен по digest официального выпуска: `ad93112d335ee687100c4c9f11bced16ca590377976b7fe7883882b9e797e472`.
- Для трёх сервисов созданы отдельные временные базы, применены настоящие миграции при запуске и SQL seed каждого сервиса. Существующие базы приложения не менялись.
- Тестовые логины совпадали с seed; пароль для этого запуска случайный, bcrypt cost 12. Пароль и cookie использовались в памяти, в отчёт и репозиторий не попали.
- Чтобы сервисы могли работать рядом на одной Windows, Go build overlay заменял **только** константы адресов прослушивания в копии `pkg/platform/server.go`: auth 55080/55081, academic 55180/55181, requests 55280/55281, все на 127.0.0.1. Рабочие файлы репозитория, обработчики и бизнес-логика не менялись.
- Caddy слушал `https://localhost:54443`. В локальной копии `deploy/Caddyfile` сохранены маршруты, удаление внешних заголовков личности и forward_auth; Docker DNS и балансировка заменены одним loopback-адресом каждого сервиса. Корень статики — существующая production-сборка T16. Это **не** проверка Docker DNS, балансировки, публичного домена и развёртывания T23.
- Для HTTPS создан временный локальный CA. Тестовый HTTP-клиент доверял его корневому сертификату; проверка сертификата не отключалась. Системное доверие Windows не менялось (`skip_install_trust`).

## Результаты

| Проверка | Фактический результат |
|---|---|
| Штатный academic `-seed-events` дважды | Каждый запуск сообщил published=18; типизированный подписчик через `pkg/events` получил 18 уникальных событий. |
| Caddy без сессии | Профиль academic → 401; поддельные X-User-* не дают войти → 401; внутренний API через внешний маршрут → 404. |
| Настоящий вход | `student.mo`, `student.meo`, `dekanat.mo`, `dekanat.meo` → 200. Сессии имеют Secure, HttpOnly, SameSite=Lax. |
| API экранов студента | Профиль, расписание 16–22.11, сводка, текущие оценки и сессии → 200. В расписании 21 строка и все статусы moved/moved_away/cancelled/changed; светофор — 3 зелёных, 2 жёлтых, 1 красная. |
| Изоляция ролей | `student.meo` с поддельными заголовками остаётся в МЭО-23-02; сотрудник МЭО не меняет занятие МО → 404; студент не меняет занятие → 403. |
| Цепочка изменений сотрудника | `dekanat.mo` переносит занятие 17.11 09:00 → 19.11 18:50 → 20.11 17:20, затем меняет аудиторию на 3047. Студент получает исходную строку moved_away и актуальную moved; API change.previous сохраняет 17.11 09:00. |
| Отмена и события | После отмены у студента одна строка cancelled на 20.11 17:20. Четыре настоящих live-события NATS имеют previous.date: 17, 19, 20, 20 ноября. В отмене previous=current=20.11 17:20, аудитория 3047. |
| Календарь после изменений | Реальный GET .ics → text/calendar с CRLF. После переноса в файле 19 занятий; после отмены — 18, UID отменённого исключён. Это проверка содержимого ответа, **не** новый импорт на телефон. |
| Публичная справка | Без сессии код K7M2QX4PWA → 200, valid=true, только шесть контрактных публичных полей. Неизвестный код → 404. |
| Истёкшая справка | Только во временной requests-БД срок seed-справки изменён на вчера. Настоящий публичный API → 200, valid=false. |
| Лимит публичной проверки | При серии запросов настоящий requests вернул 429 и Retry-After: 58. Значение зависит от оставшегося времени окна, в ТЗ не фиксируется. |
| Завершение сессии | Настоящий logout → 204. Повторный запрос с прежней cookie → 401. |

В таблице цепочка отмены и календарь раскрыты отдельно; в JSON они входят в одну группу, поэтому в отчёте 11 групп, а не 12 строк таблицы.

## Границы результата и очистка

T04: запрос расписания под `student.mo` через настоящий Caddy подтверждён локально. Развёрнутый внешний стенд не проверен. Штатные миграции и SQL seed выполнены, но сам Docker-скрипт `deploy/seed.sh` в этом Windows-запуске не использовался; его отдельно проверяет CI.

T09/T14/T15: подтверждены реальные ответы API для экранов, изменения и события. Браузерные экраны на этом запуске не открывались. Установка PWA, DevTools, Cache Storage и телефон остаются без новой ручной приёмки.

**Дополнение позднее 09.11:** выполнена отдельная [браузерная проверка с настоящим API](screenshots/runtime-api/README.md): четыре экрана на 360/1280 px, обе темы, настоящий перенос сотрудником с появлением у студента, публичная справка без входа и скачивание календаря. Границы первоначального HTTP-запуска выше сохранены; полный браузерный сценарий уведомления всё ещё зависит от T06.

`notifications` в опубликованном коде — заглушка, поэтому событие NATS **не считается** доставленным уведомлением на экране студента. Этот сквозной пункт T14 остаётся открыт до реализации T06.

После проверки остановлены запущенные процессы, удалены три временные базы и ключи локального CA. Отдельно подтверждено, что тестовая PostgreSQL остановлена, файлов CA `.key` не осталось. Cookie и пароли в файлы не записывались. В материалы PR включены только результат с вымышленными ID/слотами и этот протокол.

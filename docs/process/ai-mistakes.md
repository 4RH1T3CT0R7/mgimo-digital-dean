# Ошибки ИИ и как мы их исправили

Материал для критерия К2 («работа с ошибками ИИ»). Формат: что произошло, как заметили, как исправили, какое правило вынесли.

## M1. Правка «прошла», но файл не изменился

- **Дата и этап:** 2026-11-08, этап 2
- **Инструмент:** Claude Code
- **Что произошло:** агент обновлял `docs/progress.md` Python-скриптом через `python`. На Windows `python` оказался заглушкой Microsoft Store: команда ничего не сделала и не вернула ошибку, а агент уже закоммитил изменения.
- **Как заметили:** после коммита агент сам проверил результат (`grep` по ожидаемой строке) и получил 0 совпадений.
- **Как исправили:** правки внесены точечным редактированием файла, коммит дополнен.
- **Правило:** после любой автоматической правки проверять результат, а не код возврата. Войдёт в `AGENTS.md` как «проверяй, что изменение действительно применилось».

## M2. Неверный юридический термин в каталоге услуг

- **Дата и этап:** 2026-11-08, этап 3 (ошибка) → этап 4 (исправление)
- **Инструмент:** Claude Code
- **Что произошло:** при составлении каталога ИИ назвал мгновенную справку для действующего студента «справкой об обучении» и включил в каталог «академическую справку».
- **Как заметили:** на этапе 4 команда попросила проверить соответствие законам. ИИ стал искать ст. 60 273-ФЗ и нашёл, что «справка об обучении / о периоде обучения» выдаётся отчисленным и не прошедшим итоговую аттестацию, а академические справки не выдаются с 2013 года.
- **Как исправили:** услугу переименовали в «справку с места учёбы (подтверждение статуса обучающегося)», академическую справку заменили выпиской оценок (D30).
- **Правило:** юридические и официальные термины сверяем с первоисточником до того, как они попадут в интерфейс.

## M3. Контракты не прошли линтер OpenAPI

- **Дата и этап:** 2026-11-08, этап 5
- **Инструмент:** Claude Code (написал контракты) + Redocly CLI (проверка)
- **Что произошло:** ИИ написал 7 OpenAPI-файлов. Своим скриптом он проверил только ссылки `$ref`, потому что скачивать линтер в его сессии было запрещено. Капитан запустил линтер вручную: **13 ошибок**. Восемь из них — поля вида `allOf: [$ref] + nullable` без явного `type` (в OpenAPI 3.0 это недопустимо и могло сломать генерацию кода). Ещё пять — у внутренних API не указано, что аутентификации нет.
- **Как исправили:** ИИ добавил `type` скриптом и проверил результат подсчётом (8 из 8). У внутренних API явно указал `security: []` с пояснением (защита — изоляция сети, D31). Добавил описания тегов и `redocly.yaml` с объяснением отключённых правил. Повторный запуск — 0 ошибок, 0 предупреждений.
- **Правило:** самодельная проверка не заменяет настоящий валидатор. Линтер контрактов — обязательный шаг в CI и в задаче каркаса.

## M4. Две недоработки в контракте `auth`, которые нашлись только при реализации

- **Дата и этап:** 2026-11-08, реализация T02
- **Инструмент:** Claude Code (писал контракт на этапе 5 и сам же реализовывал сервис)
- **Что произошло:**
  1. у ответа `POST /logout` (204) в контракте не был описан заголовок `Set-Cookie` — сгенерированный код не позволял очистить cookie сессии;
  2. заголовок `X-Faculty-Id` (есть только у сотрудника) генератор сделал обязательным — студенту ушёл бы «нулевой» UUID факультета.
- **Как заметили:** при реализации по сгенерированным интерфейсам; линтер OpenAPI такие смысловые ошибки не ловит.
- **Как исправили:** в контракт добавлен `Set-Cookie` у logout; для проверки сессии написан свой тип ответа, который ставит `X-Faculty-Id` только сотруднику, с комментарием почему; тест «у студента нет X-Faculty-Id».
- **Правило:** контракт считается готовым, только когда по нему сгенерирован и скомпилирован код и написан хотя бы один хендлер.

## M5. Капитан-агент работал в worktree субагента, пока тот ещё был активен

- **Дата и этап:** 2026-11-08, реализация T08
- **Инструмент:** Claude Code (основная сессия + субагент T08)
- **Что произошло:** основная сессия влила `main` в ветку T08 прямо в worktree субагента и закоммитила перегенерированные типы API. За секунду до этого субагент закоммитил свою последнюю правку в том же worktree. Изменения не пересеклись, ничего не потерялось, но субагент увидел «чужой» merge и незакоммиченные файлы и честно о них сообщил.
- **Как заметили:** по отчёту субагента; проверка `git log origin/...` показала, что оба коммита на месте.
- **Правило:** в worktree субагента основная сессия ничего не делает, пока субагент не сообщил о завершении. Для интеграции — отдельный worktree или дождаться окончания.

## M6. Пароли тестовых аккаунтов попали в вывод команды

- **Дата и этап:** 2026-11-08, проверка оценки ответа деканата на стенде
- **Инструмент:** Claude Code (основная сессия)
- **Что произошло:** чтобы узнать логины, агент вывел строки таблицы из `.secrets/demo-accounts.md` и отрезал колонку пароля через `cut`. Но `cut` убрал только последнюю колонку («роль»), и локальные пароли тестовых аккаунтов оказались в выводе команды, то есть в журнале сессии. В репозиторий они не попали: `.secrets/` в `.gitignore`.
- **Как заметили:** агент сам увидел пароли в выводе и сообщил капитану.
- **Последствия:** это пароли локального стенда. Финальные пароли для жюри генерируются заново при деплое (T23), поэтому утёкшие нигде, кроме ноутбука капитана, не действуют.
- **Правило:** файл секретов не выводить даже частично. Нужен пароль — читать его в переменную оболочки (через `awk`, без вывода на экран) и передавать в запрос через временный файл, который сразу удаляется. Так сделана проверка на стенде в этом же PR.

## M7. Агент нарушил собственный гайд по дизайну — нашёл независимый агент-ревьюер

- **Дата и этап:** 2026-11-08, редизайн фронтенда (D52)
- **Инструмент:** Claude Code (основная сессия + агент-ревьюер без контекста обсуждения)
- **Что произошло:** основная сессия написала `docs/design.md` («то же слово — в подтверждении», «мельче 13 px — нет», «синий — только у нажимаемого») и в том же PR сама его нарушила. Примеры:
  - одно действие сотрудника называлось тремя словами: кнопка «Готово», диалог «Завершить», уведомление «Статус заявки: «Готово»»;
  - на одном экране статус назывался «Новые» в счётчиках и «Подана» в списке;
  - две страницы одной заявки (студента и сотрудника) были собраны из разных компонентов;
  - текст ошибок в тёмной теме был с контрастом 3,1:1;
  - у сотрудника нижняя панель на 4 вкладки была свёрстана на 5 колонок;
  - плитка «Готово сегодня» фильтровала все готовые заявки.
- **Как заметили:** отдельный агент получил только файлы, скриншоты и чек-лист «нейрослопа» — без хода обсуждения и без выводов основной сессии. Он вернул 25 находок со ссылками на строки; 21 исправлена в том же PR, 2 спорных решены осознанно, 2 относятся к экранам участников.
- **Правило:** гайд и код проверяет не тот, кто их писал. Для интерфейса — ревьюер с чистым контекстом и чек-листом; новые правила из его находок дописываются в гайд (`docs/design.md`, разделы «Тексты» и «Как собирать экран»).

## M8. Локальная проверка шире не стала проверкой CI

- **Дата и этап:** 2026-11-08, редизайн фронтенда (D52)
- **Инструмент:** Claude Code (основная сессия)
- **Что произошло:** агент запускал `eslint src`, а CI — `npm run lint` (`eslint .`, весь фронтенд). Новый файл `public/theme.js` лежит вне `src`, поэтому ошибки линтера (глобальные переменные браузера, пустой `catch`) нашёл только CI.
- **Как заметили:** упала задача `frontend` в PR #18.
- **Правило:** перед PR запускать ровно шаги CI (`npm run typecheck && npm run lint && npm run test && npm run build`), а не их «похожие» варианты.

## M9. Локаль C в тестовой PostgreSQL нарушила поиск по кириллице

- **Дата и этап:** 2026-11-09, T04 PR1, локальная проверка всего Go-проекта.
- **Инструмент:** Codex.
- **Что произошло:** агент поднял переносимую PostgreSQL на Windows с локалью C. Тесты нового academic прошли, но общий набор обнаружил сбой существующего теста `requests`: поиск по ФИО не находил строку при другом регистре кириллицы.
- **Как заметили:** `go test ./...` с `REQUIRE_DB_TESTS=1` упал на `TestStaffListOrderSearchAndStats`.
- **Как исправили:** заменили только изолированный локальный кластер на UTF-8 с провайдером ICU и локалью ru-RU. Код и ожидаемые значения тестов `requests` не меняли. Полный набор Go-тестов прошёл.
- **Правило:** при проверке русскоязычного поиска учитывать провайдер сопоставления и регистр кириллицы в локальной БД; сбой окружения не исправлять изменением чужой бизнес-логики или тестовых ожиданий.

## T09. Ошибки первоначальной реализации, найденные до PR

- **Дата / инструмент:** 2026-11-09, Codex.
- **Что произошло:** агент сначала обращался к ответу `/me/deadlines` как к `{ items }`, хотя контракт возвращает массив. Также использовал несуществующие имена цветовых токенов, стрелки в ссылках и синий цвет у некликабельного отсчёта.
- **Как заметили:** `tsc` выявил форму ответа; сверка с `index.css` и `docs/design.md` — ошибки оформления.

## T09. Не был обработан полный список замечаний капитана

- **Дата / инструмент:** 2026-11-09, Codex.
- **Ошибка процесса:** после просьбы исправить баги агент исправил собственные находки, но не прочитал уже опубликованные ревью PR #20/#21/#22. Отчёт о четырёх исправлениях не означал закрытия замечаний капитана; это пришлось отдельно указать участнику.

Исправлены склонение баллов, скрытие «отлично» для зачёта и единый текст отсутствия данных. V8 теперь содержит percent=100 и ECTS=A. Год поступления student.mo — 2025 по уточнению капитана.
- **Читаемость:** выбор ближайшего занятия и расчёт длительности вынесены из JSX, длинные строки основных экранов разбиты. Стиль Allman и четыре пробела сохранены по прямому указанию участника; пожелание ревью о двух пробелах ему противоречит.

- **Правило:** до отчёта о закрытии замечаний читать полный список ревью, сопоставлять каждый пункт с кодом и проверкой; зелёный CI сам по себе не закрывает ревью.

## T14. Общая строка занятия содержала студенческий адрес

- **Дата / инструмент:** 2026-11-09, Codex.
- **Что произошло:** при повторном использовании `LessonRow` ссылка исходного перенесённого занятия вела на `/schedule`, хотя сотруднику нужен `/staff/lessons`.
- **Как заметили:** сверка маршрутов при добавлении Y4; переход в студенческий маршрут нарушал бы навигацию сотрудника.
- **Исправление:** добавлен необязательный `schedulePath` в принадлежащий исполнителю компонент; исходный адрес студента остаётся значением по умолчанию. Тест проверяет адрес сотрудника.
- **Дополнительно:** в браузере после неверного ввода фокус оставался внизу панели. Добавлен перевод фокуса к первому полю с ошибкой; ошибки времени от сервера раскрывают поля собственного времени.
- **Правило:** при повторном использовании компонента проверять роль, адреса переходов и поведение фокуса, а не только его внешний вид.

## T14. Моки теряли исходный слот при последовательных изменениях

- **Дата / инструмент:** 2026-11-09, Codex, дополнительное ревью по запросу участника.
- **Ошибки:** повторный перенос перезаписывал `change.previous` промежуточным слотом; смена аудитории после переноса меняла статус на `changed` и удаляла исходную строку `moved_away`. Настоящий API сохраняет первый слот и статус `moved`.
- **Исправление:** первый слот сохраняется для всех дальнейших изменений; исходная строка пересоздаётся из него, пока занятие имеет статус `moved`. Отмена удаляет исходную строку и оставляет занятие в фактическом слоте.
- **Проверка:** три регрессионных теста выполняют изменения через MSW и читают оба расписания: сотрудника и студента. Полный набор — 120 тестов; `typecheck`, `lint`, `build` проходят.
- **Правило:** проверять не только одиночную операцию, но и последовательности перенос → перенос, перенос → аудитория, перенос → отмена; поведение моков сверять с API.

## T14. Закрытие полного списка ревью вместо собственных находок

- **Дата / инструмент:** 2026-11-09, Codex.
- **Ошибка:** агент отчитался об исправлении последовательностей в моках, не обработав остальные пункты опубликованного ревью капитана. Участник повторно указал на открытые замечания скриншотами.
- **Исправление:** отдельные подтверждения и тосты для переноса, отмены и аудитории, отмена выделена destructive. Используются общие FacultyFilter/useFacultyFilter, Select и toast; факультет и группа сохраняются в URL. Заголовки дней без capitalize, кнопки имеют описательные aria-label. У даты есть min по Москве, прошлый и неизменившийся слот не отправляются. Мок без периода возвращает текущую неделю; группа МЭО-23-02 — третий курс.
- **Проверка на опубликованной базе:** Y1–Y5, прежние цепочки и шесть новых сценариев ревью; всего 138 тестов с исправлениями T09, typecheck/lint/build и генерация проходят. В браузере на 360 px проверены подписи дней, общий Select и подтверждение отмены в тёмной теме.
- **Уточнение участника во время проверки:** «Сейчас фронт другой». Визуальная приёмка остановлена до получения ветки/PR или адреса новой версии. Результаты старой опубликованной базы не считаются проверкой нового фронта.
- **Правило:** сверять актуальную базу с участником при сообщении о новой версии и не выдавать проверку прежнего интерфейса за приёмку нового.

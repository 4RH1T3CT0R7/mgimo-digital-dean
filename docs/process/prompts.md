- **Дата:** 2026-11-08
- **Этап:** 0 → 1, старт проекта
- **Инструмент:** Claude Code
- **Зачем:** вместо «напиши мне кабинет» ИИ получает роль архитектора-партнёра и поэтапный процесс. Каждый этап подтверждаем вручную, а решения записываются в файлы, чтобы агенты Codex у других участников работали по тем же договорённостям.
- **Результат:** этап 1 — `docs/requirements.md` (требования, чек-лист критериев, 10 неясностей), структура `docs/`, журнал решений.

<context>

- Проект — личный кабинет студента для МГИМО. Цель — сдать продукт, который выполняет все требования и набирает максимум баллов по критериям из задания. Поэтому каждое решение оценивай через два вопроса: какие баллы оно закрывает и успеем ли мы его реализовать.

<instructions>
Работаем поэтапно. Не переходи к следующему этапу, пока я не подтвердил предыдущий. До утверждения плана не пиши код и не создавай файлы, кроме перечисленных в <planning_files>.

1. Анализ задания. Полностью прочитай task.txt, прежде чем делать выводы. Не додумывай требования, которых там нет. Выдели:
   - функциональные требования;
   - нефункциональные требования (стек, деплой, документация, тесты, оформление сдачи);
   - критерии оценки в виде чек-листа с баллами;
   - неясные или противоречивые места.
2. Вопросы. Задай вопросы, без ответов на которые нельзя спланировать проект: сроки, навыки участников, инфраструктура и т. п. Задавай по 3–5 за раз, начиная с самых влияющих на архитектуру. К каждому вопросу предложи варианты ответа и свою рекомендацию.
3. Референсы. Когда я пришлю скриншоты, разбери функционал: что берём, что адаптируем, что отбрасываем и почему.
4. Архитектура. Предложи 2–3 варианта и сравни их в таблице: сложность, сроки, покрытие критериев, риски для команды с AI-агентами. Дай рекомендацию.
5. Контракты. Для выбранной архитектуры опиши границы модулей или сервисов, API и модель данных настолько подробно, чтобы три агента могли работать параллельно и их части стыковались.
6. Распределение задач. Это отдельная тема для обсуждения. Предложи 2 варианта разделения работы между тремя участниками (например, по сервисам, по слоям или по фичам), с плюсами и минусами для параллельной работы через агентов. Решение примем вместе.
7. План и ТЗ. Разбей работу на этапы с приоритетами: сначала то, что обязательно для максимального балла, потом дополнительное. Для каждой задачи участника напиши ТЗ по шаблону <task_spec_template>.
</instructions>

<task_spec_template>
ТЗ пишется так, чтобы его можно было целиком вставить в Codex как задачу:
- Название и исполнитель
- Цель: зачем это нужно и какой критерий оценки закрывает
- Контекст: что агенту нужно знать о проекте, со ссылками на файлы в docs/
- Что сделать: конкретный объём работ
- Контракты: какие API, схемы и типы задача использует или предоставляет (ссылкой на docs/contracts)
- Зависимости: какие задачи должны быть готовы раньше
- Критерии готовности: проверяемые условия, включая тесты, которые должны проходить
- Что не входит в задачу: чтобы агент не расширял объём
- Оценка трудоёмкости
</task_spec_template>

## П3. Разбор референса по скриншотам

- **Дата:** 2026-11-08
- **Этап:** 3
- **Инструмент:** Claude Code (анализ изображений + веб-поиск)
- **Задача ИИ:** по 9 скриншотам чужого кабинета (lks.bmstu.ru) решить для каждого раздела «берём / адаптируем / отбрасываем» с обоснованием, затем найти в открытых источниках реалии МГИМО.
- **Что получилось:** ИИ заметил, что в референсе нет экрана «что у меня сегодня» и выделения переносов, хотя оба пункта требует задание. Он предложил не хранить лишние персональные данные: гражданство, пол, медицинские сведения. Каждую найденную реалию МГИМО ИИ пометил по надёжности.
- **Ограничение:** сайт mgimo.ru отдаёт ботам JS-проверку, поэтому ИИ опирался на поисковые выдержки и честно пометил шкалу оценок как «неизвестна, предположение».

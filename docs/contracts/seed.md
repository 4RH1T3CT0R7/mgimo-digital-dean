## Состав данных по сервисам

### academic
- Программы: ФМО — 41.03.05 «Международные отношения»; МЭО — 38.03.01 «Экономика».
- Семестр: осенний 2026/2027, 01.09.2026–27.12.2026, `is_current`.
- В каждой академической группе ещё 8–10 студентов **без логина**: нужны, чтобы у сотрудника была реалистичная статистика «кто ознакомился».
- Преподаватели — 10–12 вымышленных.
- **Расписание:** недельный шаблон на весь семестр, 3–4 пары в день пн–пт, языковые пары отдельно. Сетка пар — `data-model.md` Б4.
- **Изменения:** в каждой неделе с 16.11 по 06.12 у каждого тестового студента минимум один перенос, одна отмена и одна смена аудитории (жюри проверяет в 22–28.11).
- **Оценки:**
  - `student.mo` — семестры 1–2 завершены, всё сдано, оценки от A до E. Текущий семестр 3: 6 дисциплин, светофор 3 зелёных / 2 жёлтых / 1 красная.
  - `student.meo` — семестры 1–4 завершены, **один долг** (F в 4-м семестре). Текущий семестр 5: светофор с хотя бы одной красной.
  - Рейтинг с процентилем за последний завершённый семестр.
  - У каждой текущей дисциплины 2–4 контрольные точки.

## Формат
- Seed у каждого сервиса свой: `services/<сервис>/seed/*.sql`, применяется командой `make seed` после миграций. Каждый файл применяется ровно один раз (отметка в `_seed_applied` в той же транзакции), поэтому SQL может быть неидемпотентным.
- Уведомления по тестовым данным не пишутся в seed: их создаёт `notifications` по событиям, которые сервисы публикуют флагом `-seed-events`.
- Генерировать большие объёмы (расписание на семестр) можно SQL-запросом с `generate_series` — так seed не превращается в тысячи строк.

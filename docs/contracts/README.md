## Соглашения (общие для всех контрактов)

### Адреса и порты
- Публичный API сервиса — порт **8080**. Caddy проксирует `/api/<сервис>/*` → `<сервис>:8080`, **срезая префикс**. В контракте `servers.url = /api/<сервис>`, а пути пишутся без префикса (`/me/profile`).
- Внутренний API — порт **8081**. Caddy его **никогда не проксирует**: внутренние эндпоинты недоступны снаружи даже по подобранному адресу. Пути начинаются с `/internal/`.
- Эндпоинты студента начинаются с `/me/`, сотрудника и администратора — с `/staff/`, только администратора — с `/admin/`, публичные (без входа) — с `/public/`.

### Личность и права
- Сервис получает от шлюза заголовки `X-User-Id` (UUID), `X-User-Role` (`student` | `staff` | `admin`), `X-Faculty-Id` (UUID, только у `staff`). Читает их только через middleware `pkg/platform`.
- `/me/*` доступны только роли `student`, иначе 403.
- `/staff/*` доступны ролям `staff` (только свой факультет) и `admin` (всё), иначе 403.
- `/admin/*` доступны только роли `admin`, иначе 403 (`platform.RequireAdmin`). Действия администратора пишутся в журнал: `platform.Log(ctx).Info("admin", "event", …, "id", …)` — только ID и тип действия, без текстов и ПДн (D61).
- Чужой или несуществующий объект → **404**.
- В контрактах это описано через `security: sessionCookie` и строку «Роли:» в описании операции.

### Форматы
- ID — UUID (строка). Исключения: `service_type.id` — человекочитаемый slug, `certificate.code` — 10 символов.
- Дата и время — RFC 3339 с часовым поясом (`2026-11-20T09:00:00+03:00`). Дата — `YYYY-MM-DD`, время занятия — `HH:MM`. Всё в часовом поясе **Europe/Moscow**.
- JSON-поля — `snake_case`. Значения перечислений — латиницей, русские подписи формирует фронтенд.
- Списки с пагинацией: параметры `limit` (по умолчанию 20, максимум 100) и `offset`; ответ `{ "items": [...], "total": N }`.

### Ошибки
Все ошибки имеют один формат (схема `Error` продублирована в каждом файле, держать идентичной):

```json
{ "code": "validation_failed", "message": "Проверьте поля формы", "details": { "fields": { "reason": "Обязательное поле" } } }
```

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `validation_failed` | Неверные данные; в `details.fields` — ошибки по полям |
| 401 | `unauthenticated` | Нет сессии или она истекла |
| 401 | `invalid_credentials` | Неверный логин или пароль |
| 403 | `forbidden` | Роль не подходит (например, студент вызывает `/staff/*`) |
| 404 | `not_found` | Объекта нет **или он чужой** |
| 409 | `invalid_transition` / `conflict` | Недопустимая смена статуса или повторное действие |
| 413 | `file_too_large` | Вложение больше 5 МБ |
| 413 | `payload_too_large` | JSON-тело больше 1 МБ |
| 415 | `unsupported_file_type` | Тип файла не из белого списка |
| 415 | `unsupported_media_type` | Тело запроса не JSON и не multipart (защита от CSRF, security.md §3) |
| 429 | `too_many_attempts` | Превышен лимит; заголовок `Retry-After` |
| 500 | `internal` | Ошибка сервера (без подробностей наружу) |

`message` — по-русски, его можно показать пользователю как есть.

## Принятые на этапе 5 решения

Они же — в `decisions.md` (D31–D38).

- **Внутренний API на отдельном порту 8081** (D31). Иначе запрос `/api/academic/internal/...` прошёл бы через шлюз.
- **Слепок данных студента в заявке** (D32). При подаче заявки `requests` один раз запрашивает у `academic` ФИО, группу и курс и хранит их в заявке. Списку заявок у сотрудника не нужны внутренние вызовы, а заявка фиксирует данные на момент подачи.
- **Лента собирается по адресату при чтении** (D33). Уведомление хранится один раз, с адресатом: студент / группа / курс / факультет / все. При чтении ленты `notifications` запрашивает у `academic` принадлежность студента (факультет, курс, группы). Рассылать копии каждому студенту не нужно.
- **Факультет студента — только в `academic`** (D34). В `auth` факультет хранится только у сотрудников. Факультет заявки берётся из слепка.
- **Динамические формы заявок** (D35). Поля формы описаны в типе услуги (`fields`), фронтенд рисует форму по описанию. Новая услуга добавляется данными, без кода.
- **Сотрудник может перенести, отменить занятие или сменить аудиторию** (D36). Это даёт живую демонстрацию для жюри: сотрудник переносит пару, и студент сразу видит выделенное изменение и уведомление.
- **Имена сотрудников студенту не показываются** (D37). Ответы подписаны «Деканат ФМО»: минимизация данных и привычная практика.
- **Пароли тестовых аккаунтов не попадают в репозиторий** (D38). В seed лежат только bcrypt-хеши, пароли знают капитан и жюри.

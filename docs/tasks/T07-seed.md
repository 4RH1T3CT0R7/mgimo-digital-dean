# T07. Тестовые данные: сборка, пароли, сквозная проверка

**Исполнитель:** Капитан · **Приоритет:** P0 · **Веха:** M2

## Цель
Жюри проходит все сценарии на правдоподобных **вымышленных** данных; 5 тестовых аккаунтов с разными данными (требование задания). Критерии К3 (аккаунты работают, данные вымышленные) и К1 (видны все функции).

Seed каждого сервиса пишет его владелец:
- `academic` — T04;
- `requests` — T05;
- `notifications` — T06.

Эта задача — `auth`, связывание данных разных сервисов и сквозная проверка.

## Контекст
- `docs/contracts/seed.md` — аккаунты, общие ID, сценарий данных.
- `services/academic/seed/CHANGES.md` (из T04) — изменённые занятия.

## Что сделать
1. Seed `auth`: 5 пользователей из `seed.md`.
   - Пароли капитан задаёт локально, хеши — через `go run ./cmd/hashpw`.
   - **В репозиторий только хеши** (D38).
2. `cmd/seedevents`: публикует штатные события для данных из seed:
   - `academic.lesson.changed` для каждого изменения из `CHANGES.md`;
   - `requests.application.status_changed` для каждого перехода статуса заявок тестовых студентов;
   - `requests.application.message_added` для сообщений деканата.

   Уведомления создаёт сам `notifications` своим обычным кодом. Так данные согласованы и ничего не дублируется.
3. `make seed`: миграции → seed всех сервисов (только на пустые БД) → `seedevents`. Повторный запуск ничего не ломает.
4. Сквозная проверка по критериям ниже, исправление расхождений вместе с владельцами сервисов.

## Контракты
Таблицы из `data-model.md`, ID из `seed.md`, события из `events.md`.

## Зависимости
T04, T05, T06 (их seed), T02 (`cmd/hashpw`).

## Критерии готовности
- [ ] Все 5 аккаунтов входят.
- [ ] У `student.mo` и `student.meo` разные ФИО, факультеты, расписание, оценки, заявки.
- [ ] На неделе 16–22.11 у каждого студента видны перенос, отмена и смена аудитории, и по каждому изменению есть уведомление.
- [ ] Светофор у `student.mo`: 3 зелёных / 2 жёлтых / 1 красная; у `student.meo` есть долг.
- [ ] `dekanat.mo` видит только заявки ФМО, `admin` — заявки обоих факультетов.
- [ ] Повторный `make seed` не создаёт дублей.
- [ ] В репозитории нет паролей в открытом виде.
- [ ] Все ФИО вымышленные. В описании для жюри — оговорка о случайных совпадениях.

## Что не входит
Изменение схем и контрактов. Если данных не хватает, задачу возвращаем владельцу сервиса.

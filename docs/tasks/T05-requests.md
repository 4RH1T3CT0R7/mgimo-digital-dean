# T05. Сервис `requests` и PDF-справка

**Исполнитель:** Капитан → субагент Claude Code в отдельном worktree · **Приоритет:** P0 · **Веха:** M1

## Цель
Заявки и справки онлайн со статусом (F4) — центральный сценарий жюри «подать заявку и увидеть статус». Мгновенная справка с кодом проверки (I1), переписка с деканатом (I3), кабинет сотрудника (D7). Критерии К1, К3 (безопасность: чужую заявку не открыть).

## Контекст
- **Сначала прочитай `services/auth/README.md`** — делай сервис по тому же образцу.
- `AGENTS.md` (правила 5–13).
- `docs/contracts/data-model.md`: раздел `requests` и правила Б5, Б6, Б9.
- `docs/contracts/seed.md` — каталог услуг и поля форм.
- `docs/security.md` §3 — вложения, IDOR.

## Что сделать
1. Миграции и запросы sqlc по `data-model.md`; последовательность для `number`.
2. Каталог услуг; **валидация полей** по `ServiceType.fields`:
   - обязательность, тип, `options` для select, `max_length`;
   - дата — `YYYY-MM-DD`;
   - ошибки по ключам в `details.fields`.
3. Подача заявки:
   - слепок студента через клиент `pkg/clients/academic` (`getStudentCard`), в нём `faculty_id`;
   - статус: `submitted` или `ready` + справка в той же транзакции для `instant_certificate`;
   - `due_at`;
   - событие после коммита.
4. Статусы: функция допустимых переходов по таблице Б5 — **отдельная чистая функция**; `allowed_transitions` в ответе сотруднику; обязательный комментарий для `needs_info` и `rejected`.
5. Переписка:
   - подпись «Деканат {faculty_short}» / «Администрация» (Б9);
   - сообщение студента в `needs_info` → `in_progress`;
   - события.
6. Вложения:
   - до 5 МБ (`http.MaxBytesReader`);
   - тип по **содержимому** (`http.DetectContentType`), а не по имени;
   - хранение в `bytea`;
   - отдача с `Content-Disposition: attachment` и `X-Content-Type-Options: nosniff`.
7. Справка (Б6):
   - код base32 из `crypto/rand`;
   - PDF на лету через `github.com/go-pdf/fpdf` со встроенным шрифтом с кириллицей и лицензией OFL (например, PT Sans; файл лицензии рядом со шрифтом);
   - водяной знак, подвал, код и адрес проверки;
   - `GET /public/certificates/{code}` с лимитом 30 в минуту на IP.
8. Сотрудник:
   - staff — только `faculty_id` своего факультета (чужое → 404), admin — всё и фильтр `faculty_id`;
   - сортировка: просроченные, `due_at`, `created_at`;
   - поиск `q` по номеру и ФИО из слепка;
   - `GET /staff/stats`.

## Контракты
Предоставляет: `docs/contracts/requests.yaml`. Использует: `internal/academic.yaml` (`getStudentCard`). Публикует события `requests.application.*` (`events.md`).

## Зависимости
T02, T03, T04 PR1 (внутренний API `academic`; для тестов достаточно поддельного сервера).

## Критерии готовности
- [ ] Табличный тест **всех пар** статусов по Б5: разрешённые проходят, остальные → 409.
- [ ] Тесты валидации полей: обязательное, неверный option, неверная дата, превышение длины.
- [ ] Тесты доступа:
  - студент Б открывает заявку студента А → 404 (и через список, и по ID, и вложения, и PDF);
  - staff МЭО открывает заявку ФМО → 404;
  - студент на `/staff/*` → 403.
- [ ] Тест вложений: 6 МБ → 413; `.exe`, переименованный в `.pdf` → 415.
- [ ] PDF открывается, кириллица читается, есть водяной знак и код (скриншот в PR); проверка по коду работает, неизвестный код → 404.
- [ ] Смена статуса и сообщение сотрудника публикуют события (тест с встроенным NATS).
- [ ] `make gen` без изменений, `make test`, CI зелёные.

# T19. Тексты через ИИ: новости, услуги, справочник, пустые состояния

**Исполнитель:** Владислав Пилипенко (ИИ-ассистент для текстов + Codex для проверки формата) · **Ревью:** капитан · **Приоритет:** P1 · **Срок:** до **11.11**

## Цель
Живые, понятные тексты вместо заглушек. Это критерии К4 («понятно без инструкций», продуманные пустые состояния) и К2 («ИИ-инструменты для контента»). Справочник нужен ИИ-помощнику (T25).

## Контекст
- `docs/contracts/seed.md` — какие новости, объявления, услуги и дедлайны есть в данных.
- `docs/requirements.md` §6–7 — реалии МГИМО, каталог услуг.
- Все тексты — **вымышленные**: никаких реальных ФИО, телефонов, адресов почты.

Твой каталог: `content/` в корне репозитория.

## Стиль
- Обращение на «вы», коротко, по-человечески, без канцелярита («Справку можно скачать сразу» вместо «Справка предоставляется в электронной форме»).
- Даты — ноябрь–декабрь 2026, январь 2027.
- Пометка «концепт» в тексты не нужна: она есть в подвале.

## Что сделать (точные форматы — от них зависит импорт в тестовые данные)
1. `content/news.json` — 6 новостей:
   ```json
   [{ "title": "≤120 символов", "body": "≤1000 символов, обычный текст", "audience": "all|ФМО|МЭО", "date": "2026-11-12" }]
   ```
2. `content/announcements.json` — по 1 важному объявлению с подтверждением для ФМО и МЭО + по 1 обычному:
   ```json
   [{ "title": "...", "body": "...", "faculty": "ФМО|МЭО", "important": true, "requires_ack": true, "date": "2026-11-14" }]
   ```
3. `content/services.json` — для каждой из 7 услуг из `seed.md` (ключ — её `id`):
   ```json
   { "study-certificate": { "description": "1–2 предложения: что это и когда нужно", "hint": "подсказка под формой или null", "attachments_hint": "или null" } }
   ```
4. `content/deadlines.json` — тексты для дедлайнов из `seed.md`:
   ```json
   [{ "key": "financial-aid", "title": "...", "description": "≤300 символов" }]
   ```
5. `content/faq.md` — справочник для ИИ-помощника и людей: **25 вопросов-ответов** о порядках (справки, академический отпуск, пересдачи, материальная помощь, студенческий билет, расписание, связь с деканатом). Формат:
   ```markdown
   ## <id-латиницей>: <Вопрос>
   <Ответ, 2–5 предложений.>
   Услуга: <service_type_id или «нет»>
   ```
   Ответы — правдоподобные **общие** правила, без выдуманных номеров приказов. Где правила вуза могут отличаться — так и написать («уточните в деканате»).
6. `content/ui-texts.json` — тексты пустых состояний и ошибок по экранам:
   ```json
   { "schedule.empty_week": { "title": "...", "description": "..." }, "requests.empty": { ... }, "notifications.empty": { ... }, "error.generic": { ... }, "error.offline": { ... }, "not_found": { ... } }
   ```
   Минимум ключи: `today.no_lessons`, `schedule.empty_week`, `grades.empty`, `requests.empty`, `notifications.empty`, `deadlines.empty`, `staff.inbox_empty`, `error.generic`, `error.offline`, `not_found`.
7. **Проверка формата:** попроси Codex написать `content/check.mjs` (только Node, без зависимостей): проверяет, что все JSON валидны, длины в пределах, все 7 услуг на месте, в `faq.md` 25 записей нужного формата. Запуск: `node content/check.mjs`.
8. **Для жюри:** в `docs/process/prompts.md` — какой ИИ использовался, ключевые промпты, что пришлось исправлять.

## Контракты
Форматы выше; ключи услуг — из `seed.md`.

## Зависимости
Нет.

## Критерии готовности
- [ ] Все 6 файлов есть, `node content/check.mjs` проходит.
- [ ] Ни одного реального ФИО, телефона, e-mail (просмотреть глазами + поиск по `@` и цифрам телефонов).
- [ ] Капитан прочитал 5 случайных текстов — понятно без инструкций.
- [ ] Запись о промптах в `docs/process/prompts.md`.

## Что не входит
Импорт в БД (владельцы сервисов, T04–T07), тексты интерфейса внутри компонентов (их пишут владельцы экранов, опираясь на `ui-texts.json`).

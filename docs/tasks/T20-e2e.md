# T20. e2e-сценарий жюри на 360 px и проверки доступа

**Исполнитель:** Владислав Пилипенко (Codex) · **Ревью:** капитан · **Приоритет:** P0
**Сроки:** черновик на моках — до **15.11**, зелёный на стенде — до **18.11**, на проде — до **21.11**.

## Цель
Автоматически проверять ровно то, что будет делать жюри: войти → посмотреть расписание и оценки → подать заявку → увидеть статус. Плюс требования безопасности: «чужую заявку не открыть, даже подставив другой адрес». Критерий К3 целиком.

## Контекст — прочитай по порядку
1. `AGENTS.md`, `docs/tasks/README.md`.
2. `task.txt` — разделы «Требования к прототипу» и «Безопасность».
3. `docs/contracts/seed.md` — аккаунты и данные; `docs/plan.md` — карта экранов.
4. `docs/security.md` §3 и §6.

Твой каталог: `e2e/` (отдельный `package.json`).

## Что сделать
1. **Playwright в `e2e/`**, два проекта: `mobile` (Chromium, 360×740, `isMobile`, `hasTouch`) и `desktop` (1280×800).
   - Адрес — `BASE_URL`; пароли — переменные окружения `E2E_PASSWORD_STUDENT_MO`, `E2E_PASSWORD_STUDENT_MEO`, `E2E_PASSWORD_DEKANAT_MO`, `E2E_PASSWORD_DEKANAT_MEO`, `E2E_PASSWORD_ADMIN`.
   - **Пароли нигде не писать в код.**
2. **Селекторы** — только по ролям и подписям (`getByRole`, `getByLabel`, `getByText`), без CSS-классов. Если элемент нельзя найти по роли — это проблема доступности: запиши в PR (владелец экрана исправит).
3. **`jury-student.spec.ts`** (`student.mo`):
   1. Вход → видна главная «Сегодня».
   2. Расписание: видна метка «Перенесено».
   3. Успеваемость: видны сводка и светофор.
   4. Заявки → «Справка с места учёбы» → подать → «Справка готова» → скачивание PDF (`download`, файл `.pdf` > 0 байт).
   5. Профиль → «Выйти» → снова экран входа.
4. **`jury-staff.spec.ts`:**
   1. `student.mo` подаёт «Вопрос в деканат» с уникальным текстом и выходит.
   2. `dekanat.mo` входит, находит заявку по тексту, отвечает и ставит «Готово», выходит.
   3. `student.mo` видит статус «Ответ дан» и уведомление «Ответ по заявке №…».
5. **`security.spec.ts`** — через `request` API Playwright:

   | № | Проверка | Ожидаемо |
   |---|---|---|
   | S1 | `student.meo` запрашивает `GET /api/requests/me/applications/{id заявки student.mo}` | 404 |
   | S2 | Без cookie, но с заголовком `X-User-Id: <id student.mo>` → `GET /api/academic/me/profile` | 401 |
   | S3 | `dekanat.meo` → `GET /api/requests/staff/applications/{id заявки ФМО}` | 404 |
   | S4 | `GET /api/academic/internal/students/{id}` с cookie студента | не 200 |
   | S5 | 6 неверных паролей подряд для логина `e2e.nobody` | на 6-й попытке 429 |
   | S6 | Студент → `GET /api/requests/staff/applications` | 403 |
   | S7 | В ответах API нет полей `password`, `password_hash`, `token_hash` (поиск по телу) | не найдено |
6. **`layout.spec.ts`** (`mobile`): на каждой основной странице студента и сотрудника `document.documentElement.scrollWidth <= 360` и нет элементов, вылезающих за экран.
7. **Скрипты:** `npm run e2e` (оба проекта), `npm run e2e:mobile`; отчёт Playwright — HTML, сохраняется как артефакт в CI.
8. **CI-джоб `e2e`** (`.github/workflows/e2e.yml` — согласовать с капитаном, он владелец `.github/`; можно отдать ему файл в PR):
   - `docker compose up` + `make seed`;
   - пароли из секретов GitHub Actions (заводит капитан);
   - на PR в `main` и вручную.

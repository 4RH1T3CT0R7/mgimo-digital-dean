## Что сделать

### PR1 — лента, дедлайны, события (до 13.11)
1. Структура сервиса **как в `services/auth`**. Миграции — все таблицы `notifications` из `data-model.md`.
2. **Чистые функции** (без БД и HTTP) в `services/notifications/internal/rules/`:
   - `Matches(a Audience, m Membership, userID uuid) bool` — Б7;
   - `Render(event) (n Notification, ok bool)` — текст уведомления по шаблонам `events.md`; `ok = false`, если уведомление не нужно.
3. Клиент `academic` — сгенерированный из `pkg/clients/academic`, адрес из переменной окружения `ACADEMIC_INTERNAL_URL`.
   **В тестах — поддельный `academic`**: `httptest.Server`, который отвечает фиксированными данными по контракту `internal/academic.yaml`.
4. Эндпоинты `/me/*` по `notifications.yaml`:
   - лента, счётчики, `read`, `read-all`, `ack`, дедлайны;
   - принадлежность студента — `getStudentMembership` на каждый запрос.
5. Текущее время — только через внедряемую `now func() time.Time` (в тестах **2026-11-18 10:00 МСК**).
6. Подписчик событий через `pkg/events` (durable `notifications`):
   - `Render` → запись в `notifications` с `source_event_id`;
   - повтор события **не создаёт** второе уведомление (UNIQUE + `ON CONFLICT DO NOTHING`).
7. Seed (часть сервиса): новости, объявления с `requires_ack`, дедлайны по `seed.md`.
   - Тексты — из `content/` (T19), если готовы; иначе понятные заглушки.
   - Уведомления о переносах и заявках **в seed не пиши**: их создаст капитан в T07 через штатные события.
8. Тесты R1–R2, N1–N8 (ниже).

### PR2 — кабинет сотрудника (до 14.11)
9. `/staff/announcements` (список, создание, отчёт `acks`) и `/staff/deadlines` (список, создание, удаление):
   - staff — только свой факультет: `audience_faculty_id` подставляется сервером; группа проверяется через `getGroup`; `kind = all` для staff → 400;
   - admin — любой адресат.
10. `read_count`, `acked_count`; отчёт «кто ознакомился» — через `resolveAudience`.
11. Тесты S1–S6.

# T12. Кабинет сотрудника: заявки

**Исполнитель:** Капитан (Claude Code) · **Приоритет:** P0 · **Веха:** M2

## Цель
Вторая половина сценария жюри: сотрудник деканата видит заявку, отвечает и меняет статус, а студент сразу видит результат (D7, I3). Критерии К1 (связь с деканатом), К3.

## Контекст
`frontend/README.md`; `docs/contracts/requests.yaml` (`/staff/*`); `data-model.md` Б5.

## Что сделать
1. `/staff` — главная сотрудника:
   - счётчики `/staff/stats`: «Новые», «В работе», «Ждут студента», «Просрочены», «Готово сегодня»; нажатие → фильтр;
   - список заявок с фильтрами (статус, услуга, поиск по номеру или ФИО; у admin — факультет);
   - сначала просроченные (метка «просрочено»);
   - на телефоне — карточки.
2. `/staff/requests/:id`:
   - слепок студента (ФИО, группа, курс, факультет, № студбилета), поля, вложения, история;
   - переписка с ответом;
   - **кнопки статусов только из `allowed_transitions`**; для `needs_info` и `rejected` — обязательный комментарий в Dialog;
   - загрузка результата (`is_result`).
3. После действия — тост и обновление; ошибки 409 — понятным текстом.
4. Моки `requests` для `/staff/*`.

## Контракты
`requests.yaml`.

## Зависимости
T08.

## Критерии готовности
- [ ] Тесты:
  - кнопки только из `allowed_transitions`;
  - «Отклонить» без комментария не отправляется;
  - 409 показывается текстом;
  - фильтр «Просрочены» передаёт нужный статус.
- [ ] На настоящем API: `dekanat.mo` отвечает на вопрос `student.mo` и ставит «Готово» → у студента статус и уведомление.
- [ ] 360 px без горизонтальной прокрутки; состояния `?scenario=…`.
- [ ] CI зелёный.

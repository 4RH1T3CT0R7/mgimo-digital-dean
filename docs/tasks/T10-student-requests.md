# T10. Экраны студента: Заявки

**Исполнитель:** Капитан (Claude Code) · **Приоритет:** P0 · **Веха:** M2

## Цель
Центральный сценарий жюри: «подать заявку и увидеть её статус» (F4). Мгновенная справка (I1) и переписка с деканатом (I3). Критерии К1, К3, К4.

## Контекст
`frontend/README.md`; `docs/contracts/requests.yaml`; `docs/contracts/seed.md` (каталог услуг и поля форм); `data-model.md` Б5.

## Что сделать
1. `/requests`:
   - каталог услуг по категориям (Справки, Деканат, Финансы, Прочее) — карточки с описанием и сроком («Сразу», «до 5 дней»);
   - «Мои заявки» с фильтрами «Все» / «Пришёл ответ» и поиском по номеру;
   - на телефоне — карточки: номер, услуга, статус, дата, срок, «просрочено».
2. `/requests/new/:serviceTypeId`:
   - **форма строится по `fields`** (text, textarea, select, date — нативный `<input type=date>`, number);
   - ошибки с сервера — под полями (`fieldErrors`);
   - вложения, если разрешены (перетаскивание + выбор; лимит 5 МБ проверяется до отправки);
   - **предзаполнение из query-параметров** (`?purpose=…`) — для ИИ-помощника (T26);
   - кнопка «Подать» блокируется на время запроса.
3. После подачи справки с места учёбы — экран успеха «Справка готова» со скачиванием PDF и кодом проверки; для остальных услуг — переход в заявку.
4. `/requests/:id`:
   - шапка: номер, услуга, статус (`StatusBadge` с текстом), срок готовности;
   - **история статусов** вертикальной лентой; поля заявки;
   - **переписка** в виде чата с полем ввода; подпись деканата — `author_label`;
   - при `needs_info` — заметная плашка «Деканат просит уточнить: …»;
   - вложения со скачиванием; результат деканата выделен;
   - для справки — скачать PDF, ссылка проверки;
   - «Отозвать заявку» в `submitted` — через Dialog, не через `confirm()`.
5. Подписи статусов: submitted «Подана», in_progress «В работе», needs_info «Нужны уточнения», ready «Готово» (для вопроса — «Ответ дан»), rejected «Отклонена», cancelled «Отозвана».
6. Моки `requests`: каталог, заявки во всех статусах, мутации в памяти.

## Контракты
`requests.yaml`.

## Зависимости
T08.

## Критерии готовности
- [ ] Тесты:
  - форма из `fields` с обязательным select → ошибка без выбора;
  - 400 с `details.fields` показывается под полем;
  - справка → экран «Справка готова»;
  - сообщение в `needs_info` переводит статус в «В работе» после обновления;
  - файл больше 5 МБ отклоняется до отправки.
- [ ] 360 px без горизонтальной прокрутки; состояния `?scenario=…` на всех экранах.
- [ ] На настоящем API (после M2): полный путь «подать справку → скачать PDF → открыть проверку».
- [ ] CI зелёный.

## Что не входит
Кабинет сотрудника (T12), страница проверки (T15), ИИ-помощник (T26).

# T24. Описание процесса для жюри (PDF)

**Исполнитель:** Капитан (сборка); материалы — все участники · **Приоритет:** P0
**Сроки:** черновик — **19.11**, финал — **21.11**.

## Цель
По этому документу жюри оценивает критерий К2 «Масштаб использования нейротехнологий» целиком и частично К1. Требования — раздел «Описание процесса создания» в `task.txt`.

## Контекст
- `task.txt` — раздел «Что отправить».
- `docs/process/` — промпты, ошибки ИИ, скриншоты, опрос, аудит, лицензии.
- `docs/decisions.md`, `docs/architecture.md`, `docs/security.md`, `AGENTS.md`, `docs/tasks/` — как мы организовали работу с агентами.

## Что сделать
Документ (PDF или документ по ссылке) со скриншотами и разделами **ровно по пунктам задания**:
1. **Какую проблему решаем и почему эти разделы:** проблема (`requirements.md`) + итоги опроса (T18, «что узнали → что сделали»).
2. **Полный перечень ИИ-инструментов, IDE и сервисов** и для чего каждый: Claude Code (архитектура, контракты, бэкенд, субагенты), Codex (задачи участников), инструменты изображений (T17), текстов (T19), видео (T22) и т.д. Таблица: инструмент | кто использовал | для чего.
3. **Ключевые промпты и диалоги по этапам и функциям:** из `prompts.md`. Отдельно — как устроена работа с агентами: поэтапное планирование, `AGENTS.md` / `CLAUDE.md`, контракты как источник правды, ТЗ с тест-кейсами, плейбук для Codex, субагенты в worktree.
4. **Скриншоты ключевых шагов от первой идеи до готового кабинета,** включая неудачные варианты: из `docs/process/screenshots/`.
5. **Работа с ошибками ИИ:** из `ai-mistakes.md` (M1, M2, M3 и последующие).
6. **Как устроены вход, хранение данных и защита — простыми словами:** по `security.md` (сессия в защищённой cookie; пароли не хранятся; «чужое → не найдено»; данные в России; законы, на которые ориентировались).
7. **Этапы, проделанные вручную:** решения команды, ревью, ручные проверки, покупка домена, опрос и т.д.
8. Ссылки: прототип, репозиторий, видео; тестовые аккаунты — **только в комментарии к работе, не в документе**, если документ публичный.

Сделать документ наглядным: схема архитектуры (mermaid → картинка), таблица этапов, по одному скриншоту на функцию.

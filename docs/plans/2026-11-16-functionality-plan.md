## Потоки

### W1. Оболочка, «Полезное», студент без тупиков (только фронтенд)
- Навигация по D63: `AppShell.tsx`, `routes.tsx`, страница `/more`. Колокольчик — счётчик непрочитанных из `/me/feed/counters`.
- `/useful`: группы официальных ссылок (список ниже) и карточка деканата своего факультета. В карточке кабинет (`RoomLink` со схемой кампуса), часы приёма, вымышленная почта. Ссылки на карточку — со страницы входа («Где деканат») и из готовой заявки.
- «Сегодня»: блок «Ждёт вашего действия» — заявки `needs_info` (фильтр в API есть) и дедлайны на завтра.
- Отказ: «Подать заново» открывает форму услуги с полями отклонённой заявки.
- Долг в «Учёбе» и «сообщите в деканат» в профиле — ссылка «Спросить о пересдаче» на `/requests/new/dean-question` с предзаполнением.
- Помощник: «Не помогло — спросить деканат» с текстом вопроса.

### W2. Учебный год и сессия (academic + вкладка в «Учёбе»)
- academic: периоды семестра (учёба, зачётная неделя, сессия, каникулы) в тестовых данных и `GET /me/academic-calendar` — семестр, периоды, события студента. События: контрольные точки, зачёты, экзамены, консультации.
- В seed — зачёты декабря, консультации и экзамены января как занятия; даты совпадают с дедлайнами в notifications. `terms.end_date` сдвигается на конец сессии только **после** генерации пар.
- `.ics`: контрольные мероприятия и экзамены попадают в выгрузку.
- Фронтенд: вкладка «Учебный год» — полоса по неделям и список.

### W3. Новости, мероприятия, баннеры (notifications + фронтенд)
- Модель и API — по отчёту аналитика администратора:
  - `banners` и `banner_dismissals`;
  - у публикации-новости — `event_starts_at` и `event_place`, у прочтения — `going_at`;
  - `/me/banners`, `/me/feed/{id}/going`, `/admin/banners`;
  - `platform.RequireAdmin`, запись действий администратора в журнал.
- Обычный баннер — вверху «Сегодня», его можно закрыть. Срочный — полоса под шапкой на всех страницах студента, закрыть нельзя. В баннере только текст, ссылка — только https или внутренний путь.
- `/news`: «Все / Новости / Мероприятия». У мероприятия — дата, место, «Пойду» (сколько идёт) и «В календарь». Из ленты «Уведомлений» новости убраны.
- Сотрудник: в форме публикации — поля мероприятия. Администратор: страница «Баннеры» — создать или снять, статус и сколько закрыли.
- Тексты уведомлений: при «Готово» — комментарий сотрудника («где и когда забрать»); для вопроса — «Деканат ответил на ваш вопрос».

### W4. Студенческий и деканат (requests + фронтенд)
- requests: `GET /me/student-card` — номер, ФИО, факультет, направление, курс, срок, код проверки. QR отдаёт сервер, как в PDF справки, — новых зависимостей во фронтенде нет. Проверка по коду — через существующую `/verify`, в ответе видно, что это студенческий.
- Деканат: метка «Студент написал», когда `last_message_from = student`. В диалоге «Завершить» — подсказка «где и когда забрать» и предупреждение, если у документа нет файла-результата. Счётчики `/staff/stats?faculty_id=` для администратора (сейчас ошибка: список отфильтрован, а счётчики нет).

## Не делаем до 18.11

- Web Push и подписка webcal (.ics по ссылке).
- События об оценках, дедлайн для одного студента, список должников.
- Возврат отменённого занятия и проверка наложений.
- Отметка «студент открыл заявку».
- Управление пользователями и справочниками, редакторы «Полезного» и календаря: меняются раз в год, правятся файлом через PR.

## Общие правила для потоков

- `AGENTS.md`, `docs/design.md` (без «украшений», движение только в ответ на действие), контракт сначала, потом код (`make gen`).
- Моки MSW обновляются вместе с API: `npm run dev:mock` должен работать.
- Тесты: Go — на временном PostgreSQL, как в CI; vitest; снимки 360 и 1280 px в обеих темах.
- Тестовые данные вымышленные. Реальны только аудитории (D58) и ссылки на официальные страницы.
